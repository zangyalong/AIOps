# 配置分析与变更准备

配置问题最容易混淆“文件里写了什么”“程序实际加载了什么”和“运行对象何时读取配置”。先把这三层分开，再判断是否需要变更。

## 调查顺序

1. 确认服务的运行方式、配置入口和准确文件，不凭常见目录猜路径。
2. 读取与目标字段相邻的最小上下文，确认同名字段是否重复、是否被注释、是否存在环境覆盖。
3. 区分结构化字段修改与整文件替换。前者应形成只包含目标字段的差异，后者要核对完整新内容。
4. 查明程序加载配置的时机：每次请求读取、进程启动读取、reload 读取，或容器创建时展开。
5. 修改后分别核对文件事实、运行时事实和外部可用性，不用“文件写成功”代替“配置已生效”。

## 常见误判

- `.env` 中的值已经变化，不代表既有容器或进程重新读取了它。
- Nginx 上游地址已经正确时，故障可能在后端监听、端口映射或进程状态，不要重复修改相同配置。
- 整文件 diff 只有一行变化时，仍应先确认工具是否把完整内容误当成目标字段；字段级变更更适合使用结构化预览。
- 配置语法正确不等于服务可用，还要核验监听、健康检查和依赖状态。

涉及实际修改时，以固定运维核心与安全边界规定的预览、审批和生效流程为准；本 Skill 只提供调查方法。
