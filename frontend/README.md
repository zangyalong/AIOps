# AIOps Frontend

AIOps 的 Vue 3 前端，用于统一 Ops Agent 运维对话、事件处理、服务目录和服务器管理。

当前界面使用 Vue Router 管理真实 URL，尚未引入 Pinia；跨后端交互统一封装在 `src/api/`。
界面采用 AIOps 自有的“日光控制室”设计语言：用克制的浅色工作面承载高密度运维信息，
用深色导航和明确的运行信号建立产品辨识度。

## 当前页面

### 对话

- 新建、切换和删除历史会话
- 新对话使用 `/chat`，历史对话使用 `/chat/:conversationId`；刷新、前进/后退和复制链接可以恢复同一会话
- SSE 实时显示工具过程，并流式展示一次生成的最终回答
- 切换内部页面或关闭浏览器不会取消后端 Agent；返回生成中的会话会自动重新订阅并重放进度
- AI 回复使用 markdown-it 渲染 Markdown，并由 DOMPurify 清理 HTML；长链接、代码块和表格不会撑出消息区域
- 工具调用前的 Agent 旁白会实时显示，刷新历史后保持相同顺序
- 展示指标、日志、告警等工具调用状态；服务器指标查询合并为一张工具卡片
- SSH 只读诊断显示普通工具状态；服务重启等高风险写操作显示人工审批卡片和风险标识
- 批准或拒绝后通过 `/chat/resume` 恢复同一条 LangGraph 线程

用户看到简洁的专家旁白、调查状态和同一个 Ops Agent 的最终回答；内部执行器名称、容器挂载和策略实现不会暴露到对话界面。

### 事件中心

- 展示关联归组后的运维事件
- 按待处理、已认领、已解决筛选
- 查看事件摘要和 AI 自动诊断详情；诊断正文使用与对话一致的安全 Markdown 渲染
- 填写认领人并认领事件
- 人工标记事件为已解决

### 预警规则

- 通过页面新增、编辑、启停和删除 Prometheus 预警规则
- 规则保存到数据库；后端自动生成 Prometheus 运行时文件并热重载，无需手工修改 YAML

### 服务目录

- 新增、编辑和删除逻辑服务，维护环境和服务说明
- 将服务部署实例绑定到已有服务器，并分别配置 Prometheus `instance` 与 Loki `service_name`
- 直接查看服务运行状态、Prometheus 关键指标和 Loki 近期日志

### 服务器

- 查看、新增、编辑和删除纳管服务器
- 配置 SSH 用户、端口、私钥文件名和目标服务器部署参数
- 测试 SSH 连通性
- 生成首次安装包，或通过受控入口应用已经保存的目标服务器配置

### Memory

- 按全局或服务器作用域查看、搜索长期记忆
- 手动添加经过后端安全校验的稳定信息
- 删除单条记忆；Agent 也会从成功对话中提炼可复用信息

### Skills

- 搜索并查看后端实际安装的运维 Skill
- 在详情弹窗中阅读完整 Markdown 方法说明
- 只展示名称、描述和正文，不暴露内部路径或工具绑定

## 技术栈

- Vue 3.5
- Vue Router 4
- markdown-it + DOMPurify
- TypeScript 6
- Vite 8
- Composition API + `<script setup>`
- 原生 `fetch` 和 `ReadableStream` 处理 API/SSE

## 界面与样式约定

### 设计方向

界面服务于值班工程师快速判断状态和进入处置，不追求营销页面式的装饰。视觉大胆度集中在
导航信号轨和运维助手空态的“示波器信号”上，其余区域依靠对齐、留白、分隔线和字体层级组织信息。

设计时遵守以下原则：

- 状态优先：运行状态、风险等级、目标服务器和待执行动作必须比装饰更醒目。
- 信息结构优先：只有真实序列才使用编号；英文 eyebrow 用于表达当前位置，不作为无意义装饰。
- 阴影克制：普通数据卡片默认只使用边框，悬停时才出现轻微阴影和位移；弹窗可以使用强阴影。
- 一个区域只保留一个主要动作，危险操作不能使用主强调色伪装成普通动作。
- 不使用 emoji 作为功能图标；导航图标使用统一的线性 SVG。

### 全局设计令牌

所有跨页面使用的颜色、字体、圆角和阴影都定义在 `src/style.css` 的 `:root` 中。新增页面优先复用变量，
不要在多个组件里重复写相近的十六进制颜色。

| 令牌 | 当前值 | 用途 |
| --- | --- | --- |
| `--color-bg` | `#eef2f4` | 应用外围和浅色工作台底色 |
| `--color-surface` | `#f9fbfc` | 页面主工作面 |
| `--color-surface-strong` | `#ffffff` | 卡片、输入框和需要抬高的内容 |
| `--color-border` | `#d8e0e4` | 常规分隔线与卡片边框 |
| `--color-text` | `#14232c` | 主要文字 |
| `--color-text-muted` | `#687780` | 说明、时间和次要信息 |
| `--color-accent` | `#16899a` | 主要操作、选中态和运行信号 |
| `--color-status-active` | `#23856d` | 正常、在线、成功 |
| `--color-status-unconfigured` | `#d9872c` | 未配置、需要关注 |
| `--color-status-unreachable` | `#cf4b48` | 失败、危险、不可达 |

状态不能只靠颜色表达，旁边必须同时有文字、图标或形状。例如红色圆点旁仍要显示“连接失败”。

### 字体角色

- `--font-display`：页面标题、面板标题和关键数字。使用较窄字面建立控制台感，但不要用于长正文。
- `--font-body`：正文、按钮、表单和说明文字。
- `--font-data`：IP、端口、PromQL、日志、路径、时间、状态标签和英文 eyebrow。
- 全局启用等宽数字，指标和时间变化时不会发生明显横向跳动。

字体栈只使用系统可用字体，目前不依赖外部字体 CDN，避免离线或内网环境下界面突然换版。

### 页面布局

桌面端应用骨架由 224px 深色主导航和带 10px 外间距的工作面组成。普通列表页使用以下页头层级：

```vue
<header class="view-header">
  <div>
    <span class="view-kicker">DOMAIN / CURRENT AREA</span>
    <h1>页面名称</h1>
    <p class="subtitle">说明这个页面可以查看或控制什么</p>
  </div>
  <button type="button" class="btn-primary">主要动作</button>
</header>
```

- `view-kicker` 必须反映真实信息层级，例如 `INFRASTRUCTURE / NODES`，不要使用空泛文案。
- 列表页内容宽度按信息密度控制在约 1180–1240px；服务目录允许使用更宽的双栏工作区。
- 页面主体可滚动，应用外壳和聊天/服务目录内部区域负责各自的滚动边界，避免产生双滚动条。
- 760px 以下主导航切换为底部栏；640px 以下隐藏聊天历史侧栏，把空间留给当前对话。
- 新增页面至少检查 390px 手机宽度，不允许出现页面级横向滚动。

### 组件样式

按钮：

- 主按钮使用 `--color-accent`，同一操作组尽量只有一个。
- 次按钮使用透明或白色背景加边框；文字按钮只用于低权重操作。
- 删除、停止和其他危险操作使用 `--color-status-unreachable`，并保留明确动作文字。
- 普通按钮和表单控件的最小高度为 38–40px；禁用态既降低视觉权重，也必须设置真实 `disabled`。

卡片与状态：

- 常规卡片使用 9–10px 圆角、`--color-border` 边框和白色表面，默认不加厚重阴影。
- 状态标签使用小圆角矩形，不统一做成胶囊；胶囊只留给确实需要表达独立标签的内容。
- 指标、规则表达式和服务器地址优先使用 `--font-data`，正文描述仍使用 `--font-body`。
- 空状态要说明“为什么为空”和“下一步做什么”，不能只显示一张装饰图。

图标与动效：

- 功能图标使用 `24 × 24` viewBox、`currentColor` 描边、圆角端点，常规描边宽度约 `1.65`。
- 动效用于反馈状态变化，常规过渡控制在 150–180ms；不要给所有卡片添加持续漂浮或发光效果。
- 全局已经处理 `prefers-reduced-motion`，新增长动画时仍需确认减少动画模式下信息不会丢失。

### CSS 编写规则

- 全局令牌、表单基础态、键盘焦点和滚动条放在 `src/style.css`。
- 页面或组件特有样式放在对应 Vue 文件的 `<style scoped>` 中，不建立没有实际复用场景的抽象层。
- 选择器优先使用单一 class，避免用元素选择器和高层级嵌套与组件 class 互相覆盖。
- 颜色、圆角和阴影先查现有变量；确实只属于一个局部视觉时才允许写局部值。
- 新增交互必须有 `:hover`、`:focus-visible`、`:disabled`；可点击的非按钮元素需要键盘行为和正确语义。
- 中文界面使用主动、具体的动作名称，例如“保存规则”“标记为已解决”，不要使用含糊的“提交”“确定”。

## 环境要求

- Node.js `^20.19.0` 或 `>=22.12.0`
- npm
- AIOps 后端运行在 `http://127.0.0.1:8010`

## 安装与启动

```bash
cd frontend
npm install
npm run dev
```

Vite 固定使用 5174 端口：<http://127.0.0.1:5174>。

如果该端口已占用，Vite 会直接退出而不是自动换端口；需要先处理占用，或临时设置：

```bash
PORT=5175 npm run dev
```

## 后端代理

浏览器里的所有后端请求都写成 `/api/...`。开发服务器按照 `vite.config.ts` 转发：

```text
浏览器 /api/incidents
    ↓ 去掉 /api 前缀
FastAPI http://127.0.0.1:8010/incidents
```

因此前端代码不需要硬编码后端域名，也不会在本地开发时遇到跨域问题。生产构建后需要由反向代理
提供等价的 `/api` 转发规则，并把 `/chat/*`、`/incidents`、`/alert-rules`、`/services/*`、`/servers` 等前端路由回退到
`index.html`，否则直接刷新历史对话 URL 会得到 404。

## 数据流说明

### 普通对话

```text
ChatView → POST /api/chat 创建 Chat Run
         → GET /api/chat/runs/{run_id}/events 订阅/重连
         → SSE 工具事件实时展示 → 一次生成并流式展示最终回答 → done
```

Chat Run 在后端独立执行，浏览器的 SSE 只是订阅者。对话页卸载时会主动关闭当前订阅以节省连接，
但后台任务继续；再次打开 `/chat/:conversationId` 时先加载数据库历史，再查询活跃运行并重放未完成轨迹。

### 写操作审批

```text
Agent 提议重启白名单内的 systemd 服务
    ↓
approval_required（带 thread_id）
    ↓
中风险：用户在审批卡片批准或拒绝
高风险：用户点击执行后，在展示目标和动作的详情弹窗再次确认
    ↓
POST /api/chat/resume
    ↓
恢复原 LangGraph 执行并继续 SSE
```

在审批完成前，输入框会被禁用，防止用户开启新一轮后遗留未恢复的挂起线程。

## 运行时验收

后端和前端均已运行时，可以按下面顺序检查：

1. 打开“服务器”，确认列表能够加载并测试一台已配置服务器。
2. 打开“事件中心”，确认事件筛选、诊断详情、认领和解决操作。
3. 打开“服务目录”创建服务并绑定服务器，确认状态、指标、日志和实例管理正常。
4. 请求在测试服务器执行 `uptime`，确认它作为只读诊断直接执行，不出现审批卡片。
5. 请求重启一个服务，确认先出现高风险审批卡片，点击执行后再出现目标详情弹窗；取消或拒绝都不执行，弹窗确认后仍需通过后端二次确认校验和服务白名单。
6. 刷新会话，确认消息、工具轨迹和审批结果可以从历史记录恢复。
7. AI 生成途中切到“事件中心”或“服务器”，再点击“对话”，确认 URL 回到原会话并继续显示进度。
8. AI 生成途中关闭页面，再用同一 `/chat/:conversationId` 地址打开，确认任务继续并最终入库。
9. 分别在桌面宽度和约 390px 手机宽度检查主要页面，确认底部导航、卡片和弹窗没有横向溢出。

## 当前限制

- 没有登录、用户身份和前端 RBAC。
- 事件认领人暂时由用户自由输入，后续应由登录身份提供。
- 正在执行工具或生成回答的 Chat Run 仍依赖当前 FastAPI 进程，后端重启后会失败关闭；只有尚未执行、正等待人工审批且 checkpoint/审计完全匹配的断点可以恢复。
- 生产部署需要自行配置静态文件托管和 `/api` 反向代理。
